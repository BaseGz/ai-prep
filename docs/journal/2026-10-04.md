## save_note：路径安全不是「删掉坏字符」

最初想法是黑名单 —— 把 `../` 和非法字符删掉。三个用例全部漏网：

| 输入 | 黑名单为什么失效 |
|---|---|
| `....//` | 删掉中间的 `../` 后剩下的 `..` 和 `/` 又拼出一个新的 `../` |
| `..\..\x` | `replace("../", "")` 完全没命中，因为反斜杠 |
| `C:\Windows\x` | Path 的 `/` 遇到右侧**绝对路径**会整个丢掉左边 |

最后改成**白名单 + 结果判定**：只保留 `isalnum()` 和 `-_ `，其余换成下划线；
再用 `p.resolve()` 求出真实落点，断言 `p.parent == NOTES_DIR.resolve()`。

两个实测副产品：
- `NUL` 这类 Windows 保留设备名会「写入成功」，但 `exists()` 为 True、`size` 是 0 —— 必须自己判。
- 本机 `PYTHONUTF8=1`，不写 `encoding` 也恰好不出错，**那是假象**，换台机器就炸。

## calc：eval 与 ast 的对照

| 输入 | `eval` 版 | `ast` 版 |
|---|---|---|
| `(128+72)*3` | 600 | 600 |
| `10/4` | 2.5 | 2.5 |
| `-5*2` | -10 | -10 |
| `1/0` | ZeroDivisionError | 算不了：division by zero |
| `__import__('os').getcwd()` | **返回项目路径** | 算不了：不支持的写法：Call |
| `2**10` | 1024 | 算不了：不支持的运算符：Pow |

关键认知：**白名单不是「识别坏东西」，是只承认三种好东西**（`Constant` / `BinOp` / `UnaryOp`），
其余节点连解释都不解释就拒。跟 save_note 里那个「resolve 之后再判父目录」是同一个思路 ——
先得出结论，再判定结论。

代价也要记住：`2**10` 被拒不是 bug，是能力边界。想支持就显式加 `ast.Pow`，
但要同时想到 `2**999999999` 会把内存吃光。

## 今天的坑：残缺 checkpoint 会被永久留下

新进程启动，第一句就 400：

```
An assistant message with 'tool_calls' must be followed by tool messages
responding to each 'tool_call_id'.
```

原因是 11-16 那次 `calc` 还抛 `NotImplementedError`，图中断在「model 输出了 tool_calls、
tools 没执行」，而这个半截状态被 checkpoint 存了下来。今天读回来，历史里
`AIMessage(tool_calls=[calc])` 后面直接跟了一条 `HumanMessage`。

**checkpoint 不是事务，它每个 super-step 提交一次，所以「做了一半」也会被记住，而且不会自愈。**

详细定位过程见 `errors/index.md` 的 D14 条目。处理方式：把坏库改名成 `broken-assistant.db`
（仍在 `.gitignore` 的 `*.db` 覆盖范围内），从空库重跑。
