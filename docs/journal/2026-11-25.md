## 一句话结论

**参数不触发，内容再多也不动。** 这条今天验了三遍：`separators` 在段落装得下时完全不登场
（size=300 加不加「。」都是 7 块）；`add_start_index` 不加就没有 `start_index`；
`split_text` 那条路连 metadata 都不存在。切分器不会「顺便帮你做对」，它只执行你给的那份配置。

配套第二句：**上限从来不是下限。** 字符尺会切出 9 字的块，token 尺会切出 8 个 token 的块，
换什么尺子都一样。

### d5：加分隔符，然后发现它不是万能药

两个 size × 两套配置并排跑：

| size | 配置 | 块数 | 各块长度 |
|---|---|---|---|
| 200 | 默认 | 12 | 151, 144, 198, **9**, 165, 199, **19, 72**, 166, 163, 90, 127 |
| 200 | 加句号 | **11** | 151, 144, 198, 9, **130, 190, 137**, 166, 163, 90, 127 |
| 300 | 默认 | 7 | 297, 209, 165, 291, 247, 174, 127 |
| 300 | 加句号 | 7 | 297, 209, **256, 201**, 247, 174, 127 |

**只有 200 变了。** 原因是 200 太小，段落普遍装不下，切分器必须一路降级到「按空格切」——
中文没有空格，于是退成逐字硬切，切出 19、72 这种碎片。加上「。」之后它才第一次有了中文边界，
碎片被合并成 130 / 190 / 137。

**300 一个块都没少**，只是中间两块挪了位置（165+291 → 256+201）。

这和第二级那条是同一件事：**分隔符只在「某一片自己就超过上限」的时候才被调用。**
段落装得下时，它是装饰品。

### d6：metadata 到底穿不穿得过

同一份 doc、同一个配置，走两个入口：

| 入口 | 数量 | 元素类型 | 第 0 个的 metadata |
|---|---|---|---|
| `split_text(git_data)` | 7 | `str` | 不存在 |
| `split_documents([doc])` | 7 | `Document` | `{'source': 'git-guide.txt'}` |

**数量一样、类型不同**——这是最容易麻痹人的地方：不报错、块数也对，只有 metadata 静默消失。
`str` 不是「丢了」metadata，是它天生没有这个字段。

第三个对象加了 `add_start_index=True`，前 5 块的起点是 `[0, 299, 510, 766, 969]`。
它记的是**这一块在原文里的起始字符位置**，将来做「高亮原文出处」全靠它。

### d7：换一把尺子

```
1522 字 = 1452 token     → 1 token ≈ 1.05 字
token 尺 256/32          → 9 块
每块 token: [224, 248, 8, 161, 237, 79, 212, 193, 109]
```

同一份 1522 字的文档：字符尺 300 → 7 块，token 尺 256 → 9 块。**块数不是算出来的，换尺子就换结果。**

比值 1.05 和 `chunking.py` 里 journal 那份的 1.30 不一样，因为这份有 `- feat：` 这种列表和
`merge message` 这种英文词——英文常被拆成两三个 token。**比值跟着内容走，不能背系数。**

最后那个 8 个 token 的块，再次证明：`chunk_size` 是上限，不是下限。

## 今天踩的坑

| 写法 | 结果 | 根因 |
|---|---|---|
| 用 `Document(...)` 但只 import 了 splitter | `NameError: Document` | `from langchain_core.documents import Document` |
| `split_documents([docs])` | `'list' object has no attribute 'page_content'` | `docs` 本身已是 list，多包一层变成 list[list[Document]] |
| `chunks_list_1.metadata` | `'list' object has no attribute 'metadata'` | 属性在**某一块**上，要写 `[0].metadata` |

第一个和第三个是同一类错的镜像：d2 那次 `create_documents(git_data)` **少**了方括号，
把字符串逐字符拆成 1522 个 Document；今天**多**了方括号，把 list 又包了一层。

规则不是「记住加几个括号」，是：**先看手里的变量是什么形状，再看函数要什么形状。**

## 三个小知识

1. `metadata` 不是给模型看的，是给检索链路看的。`source` 用来溯源、`section` 用来过滤
   （D19 时 `filter={"section": "troubleshooting"}`）、`start_index` 用来高亮原文。
   不手动格式化进 prompt 的话，模型根本读不到它。
2. `from_tiktoken_encoder` 是**类方法**，它造的是一个新对象（内部把 `length_function` 换成了
   `enc.encode`），不是给已有对象换尺子。写 `RecursiveCharacterTextSplitter.from_tiktoken_encoder(...)`。
3. 中文标识符在 Python 3 合法，但 `git diff`、`grep`、调试器都不友好。d5 骨架里的
   `("默认", sp1)` 只是占位写法，实际代码用英文 `label`、`sp_plain`、`sp_punct`。
