# 2026-10-03 · D13 记忆持久化

## 一句话结论

持久化存的不是对话文本，是**图的每一个 super-step** —— 一轮对话 3 个 checkpoint，
「记住」在工程上等于：**一张表 + 一个 id + 一个连接**。

## 今天的坑：连接不能跨线程

**现象**：把 `sqlite3.connect(DB, check_same_thread=False)` 里的参数删掉，启动日志正常打印
「已有 6 条消息、历史 checkpoint 9 个」，一执行 `agent.invoke(...)` 就抛：

```
sqlite3.ProgrammingError: SQLite objects created in a thread can only be used in that
same thread. The object was created in thread id 46444 and this is thread id 58880.
```

**我以为**：`connect` 写在 `main()` 里，整个脚本从头到尾就在一个线程跑；SQLite 是单文件数据库，
`check_same_thread` 只是「多加一层保险」，删了顶多并发时慢一点。

**实际**：**读在主线程，写在线程池。** LangGraph 的 Pregel 执行器把 `checkpointer.put`
交给 `ThreadPoolExecutor` 的 worker 线程执行，而 sqlite3 默认 `check_same_thread=True`，
规定「这个连接只能由创建它的线程用」。所以 `get_state` / `get_state_history` 能过，
`invoke` 一写 checkpoint 就炸。

**怎么定位到的**：看 traceback 的三帧，不是一条线跑下去的：

```
_loop.py:1545      checkpointer.put(...)        ← 要写库了
_executor.py:80    done → thread.py:59 run      ← 在 worker 线程里
sqlite/__init__.py:437 put → cursor()          ← 拿到连接就报错
```

异常在 `58880` 线程发生，但由主线程 `46444` 的 `future.result()` 重新抛出 ——
**栈里同时有两种帧，因为它是跨线程拼起来的栈**，不是一条调用链。

**结论**：一个 sqlite 连接要跨线程用，必须显式关掉这个检查，把并发控制交回给 SQLite 自己的锁。

## 三个实验

1. **换 `thread_id`（u2）**：启动 `0 条消息、0 个 checkpoint`，而同一个 db 文件、同一个 agent，
   u1 的 6 行纹丝不动。换 id 就是换一个人，表里只按 `thread_id` 分链。
2. **打印 `get_state_history`**：6 行，`step` 从 4 倒到 -1，消息数 `4 → 3 → 2 → 2 → 1 → 0`。
   `source=input` 是「用户说话了」，`source=loop` 是「节点跑完了」。
   一轮 3 个 checkpoint 的真实构成是：**input（收到）→ `__start__`（写进 state）→ model（跑完）**。
3. **换回 `InMemorySaver`**：第二次启动回到 0 条，db 文件大小不动 —— D12 结尾的判断被证实：
   进程一退就失忆，这就是今天要换掉它的理由。

## 加工具之后的意外

给 agent 加上 `find_order`，换新 thread（u4）跑一轮：

```
[启动] thread=u4 已有 0 条消息，历史 checkpoint 0 个
[结束] 库里 4 条消息，checkpoint 5 个
checkpoints: 26 行
writes: 28 行          ← 第一次出现两个数不相等
```

之前一直是 6/6、12/12、21/21，今天第一次 26 vs 28。查库发现 write 是按 channel 分的：

| channel | u1（两轮，无工具） | u4（一轮，带工具） |
|---|---|---|
| `messages` | 6 | 4 |
| `branch:to:model` | 3 | 2 |
| `__pregel_tasks` | 0 | **1** |

`__pregel_tasks` 只有带工具才有 —— 它记的是「把活派给 tools」。
所以：**checkpoint 是快照，write 是这个快照里每个任务往哪个通道写了什么。
一个快照可以装 0 条、1 条或 2 条写入。**

## 今天最反直觉的一件事

想做一次干净的「第一次运行」，光删 `memory.db` 就行了吗？不行 —— 因为 u3 在我改代码之前
已经跑过一次（留下的 2 条消息），改完代码再跑，它直接走 `else` 分支问「我叫什么」，
**模型压根不会去调工具**，checkpoint 从 3 涨到 6，看起来像正常结果，其实什么都没验证。

持久化的好处是能续聊，代价是**每次实验都不再是干净开局**。想复现「第一次」，必须换一个
没人用过的 `thread_id`。
