4.1 建文件，整段粘贴

这段我在你的 venv 里跨两次进程跑过，预期输出见 4.2。 设计上它第一次跑「建立记忆」、第二次跑「验证记忆」，所以同一份代码跑两次，行为不同 —— 这就是跨进程。

"""D13 · 记忆持久化：SQLite checkpointer，重启不丢上下文"""
import sqlite3
import sys
from pathlib import Path

DAY09 = Path(__file__).resolve().parents[1] / "day09-handwritten-agent"
sys.path.insert(0, str(DAY09))

from langchain.agents import create_agent
from langgraph.checkpoint.sqlite import SqliteSaver

from agent_loop import model

DB = Path(__file__).with_name("memory.db")
THREAD = "u1"
SYSTEM = "你是一个简洁的助手，回答不超过两句话。"


def build():
    """一句 sqlite3.connect + 一个 SqliteSaver，就是全部持久化配置"""
    conn = sqlite3.connect(DB, check_same_thread=False)
    agent = create_agent(model, [], system_prompt=SYSTEM, checkpointer=SqliteSaver(conn))
    return agent, conn


def show_tables(conn):
    """直接查库，眼见为实"""
    names = [r[0] for r in conn.execute(
        "select name from sqlite_master where type='table' order by name")]
    print("  库里的表：", names)
    for t in names:
        n = conn.execute(f"select count(*) from {t}").fetchone()[0]
        print(f"    {t}: {n} 行")


def main():
    size_before = DB.stat().st_size if DB.exists() else 0
    agent, conn = build()
    cfg = {"configurable": {"thread_id": THREAD}}

    snap = agent.get_state(cfg)
    history = list(agent.get_state_history(cfg))
    msgs = snap.values.get("messages", []) or []
    print(f"[启动] 数据库 {DB.name} 大小 {size_before} 字节")
    print(f"[启动] thread={THREAD} 已有 {len(msgs)} 条消息，历史 checkpoint {len(history)} 个")

    if not msgs:
        print("[第一次运行] 库里是空的 —— 先建立记忆")
        r = agent.invoke({"messages": [{"role": "user", "content": "我叫 Base，我在准备 AI 实习"}]}, cfg)
    else:
        print("[第二次运行] 新进程，库里已有记录 —— 直接验证它记不记得")
        r = agent.invoke({"messages": [{"role": "user", "content": "我叫什么？我在准备什么？"}]}, cfg)

    print("  答：", str(r["messages"][-1].content)[:80])
    print(f"  本轮结束后 {len(r['messages'])} 条")

    snap2 = agent.get_state(cfg)
    print(f"[结束] 库里 {len(snap2.values['messages'])} 条消息，"
          f"checkpoint {len(list(agent.get_state_history(cfg)))} 个，"
          f"文件 {DB.stat().st_size} 字节")
    show_tables(conn)
    conn.close()


if __name__ == "__main__":
    main()

「你的活」两处（必须自己改）

  1. 把 check_same_thread=False 删掉，看会发生什么。 跑一次，抄下报错原文。 判定标准：能说出「为什么 LangGraph 需要它」—— 提示：报错里有两个不同的 thread id，一个是你建连接的线程，一个是执行节点的线程。 这条是今天的核心坑，比记住 API 重要。

feat(day13): 对话历史落 SQLite，换掉 InMemorySaver 后重启仍能续聊

现象：
同一份脚本，第一次运行库里 0 条、答完写入 2 条、文件 4096 字节；
关掉进程重新启动，启动日志显示「已有 2 条消息、3 个 checkpoint」，
直接问「我叫什么」答出「你叫 Base，你在准备 AI 实习」。

我以为：
把对话存成文本追加到文件里就够了，读回来拼进 messages 即可；
持久化就是把 messages 序列化。

做法：
sqlite3.connect(DB, check_same_thread=False) + SqliteSaver(conn) 一个构造参数换掉 InMemorySaver；
用 get_state / get_state_history 读回来，用 sqlite_master 直接查表看结构；
三个实验：换 thread_id、打印 checkpoint 明细、换回 InMemorySaver 对照。

结论：
持久化存的不是对话文本，是图的每一个 super-step —— 一轮对话 3 个 checkpoint，
表里是 checkpoints + writes 两张，按 thread_id 索引。
「记住」在工程上等于：一张表 + 一个 id + 一个连接；
而连接必须跨线程，因为执行节点的不止一个线程。

第 2 次：文档

勾选：docs/journal/2026-10-03.md、docs/decisions.md、 errors/index.md、docs/progress.md、README.md。

docs(day13): 持久化不是存对话，是存每一个 super-step

现象：
第一轮对话 2 条消息，库里却是 3 个 checkpoint、3 行 writes；
删掉 check_same_thread=False 直接报 ProgrammingError，两个线程 id 对不上。

我以为：
checkpoint 数应该等于轮数；SQLite 是单文件、单进程，加线程参数是多余的小心。

做法：
把 get_state_history 的 step / source / next / 消息数逐条打出来，
确认 step=-1 是输入、step=0 之后是节点执行；
再删掉 check_same_thread=False 复现报错，抄下两个线程 id。

结论：
super-step 才是持久化的最小单位，一轮对话是多个 super-step 拼出来的。
文档没写 check_same_thread，因为那是 sqlite3 的常识、不是 LangGraph 的 API ——
这类「文档缺口」只能靠跑出来补。
