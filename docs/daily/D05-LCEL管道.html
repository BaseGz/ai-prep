4动手 · 写 lcel_demo.py

新建 week1-basics/day05-lcel/lcel_demo.py。 骨架在下面，可以直接粘；模型初始化那段和你 D1 的 hello_model.py 完全一致（同样读仓库根的 .env、同样走 OpenAI 兼容协议）。

今天的所有内容，就是这一行：

chain = prompt | model | StrOutputParser()

三个东西都是 Runnable，所以能串。prompt 的输出是消息列表， model 正好收消息列表；model 输出 AIMessage， StrOutputParser 把它变成字符串。环节之间的输入输出对得上，管道就通。

"""D5 · LCEL 管道（最小可运行）

今天验证三件事：
① 管道符 | 到底做了什么 —— 上一个 Runnable 的输出 = 下一个的输入
② 同一条 chain，四种调用方式都成立：invoke / stream / batch / ainvoke
③ 形状对不上时怎么排查 —— 先看「第一个环节要什么输入」
"""
from __future__ import annotations

import asyncio
import os
import time
from pathlib import Path

from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate

REPO_ROOT = Path(__file__).resolve().parents[2]
load_dotenv(REPO_ROOT / ".env")

MODEL = os.getenv("DEEPSEEK_MODEL", "deepseek-chat")
BASE_URL = os.getenv("DEEPSEEK_BASE_URL", "https://api.deepseek.com/v1")
API_KEY = os.getenv("DEEPSEEK_API_KEY")


def build_chain():
    """把三个 Runnable 串成一条链。今天要理解的就是这一行。"""
    if not API_KEY:
        raise SystemExit("没读到 DEEPSEEK_API_KEY，先检查仓库根的 .env。")

    prompt = ChatPromptTemplate.from_messages([
        ("system", "你是一个说话极简的中文助手，回答不超过 30 个字。"),
        ("user", "{question}"),          # ← 这个占位符，决定了 invoke 要传字典
    ])
    model = init_chat_model(
        MODEL,
        model_provider="openai",
        base_url=BASE_URL,
        api_key=API_KEY,
        temperature=0,
    )
    return prompt | model | StrOutputParser()


def main() -> None:
    chain = build_chain()

    # ① invoke —— 同步，一次一个问题
    print("① invoke：", chain.invoke({"question": "用一句话解释什么是管道符"}))

    # ② stream —— 逐块拿，打字机效果的来源
    print("② stream：", end="", flush=True)     # flush 必须有，否则看不到逐字效果
    for chunk in chain.stream({"question": "写一句关于管道符的顺口溜"}):
        print(chunk, end="", flush=True)
    print()

    # ③ batch —— 一次给多个输入，内部并发
    answers = chain.batch([
        {"question": "1 的三次方是多少"},
        {"question": "2 的三次方是多少"},
        {"question": "3 的三次方是多少"},
    ])
    print("③ batch：", answers)

    # ④ ainvoke —— 异步版本，顶层不能 await，用 asyncio.run 包
    print("④ ainvoke：", asyncio.run(chain.ainvoke({"question": "用一句话介绍你自己"})))

    # ⑤ 附赠：batch 和 for 循环的耗时对比（今天的实验数据）
    questions = [{"question": f"{n} 的三次方是多少"} for n in range(1, 6)]

    t0 = time.perf_counter()
    for q in questions:
        chain.invoke(q)
    t_for = time.perf_counter() - t0

    t0 = time.perf_counter()
    chain.batch(questions)
    t_batch = time.perf_counter() - t0

    print(f"⑤ 5 个问题：for+invoke {t_for:.2f}s ／ batch {t_batch:.2f}s")


if __name__ == "__main__":
    main()

三处要你自己动脑子改的地方

  1. 把 | StrOutputParser() 去掉再跑一遍，看 print 出来是什么。 你会拿到一个 AIMessage 对象而不是文字 —— 这一步是理解「管道两端形状要匹配」的最快方式， 也是今天最值得写进 commit 的一句话。
  2. 故意传错输入：写一次 chain.invoke("你好")（字符串，不是字典）。 记下报错信息长什么样 —— 以后看到类似报错，你就知道是第一个环节在要变量。
  3. 给 for + invoke 和 batch 各记一个数，不要预设结论。 谁快谁慢取决于网络和并发限制，你测出来的数才是数据。

6坑预警

症状真实原因
chain.invoke("你好") 报错，或输出里把整个字符串当成了变量 链的第一个环节是 prompt，它要的是变量字典。正确写法是 chain.invoke({"question": "你好"})。 记住对比：model.invoke() 收消息列表，chain.invoke() 收字典 —— 看链的入口是谁
print 出来是 AIMessage(content=...) 一大坨 忘了接 | StrOutputParser()。这不是报错，是类型没转换 —— 今天正好拿它当实验
stream 看不出逐字效果，还是一次性全出来 两个原因：① 忘了 flush=True（PyCharm 控制台会缓冲）； ② 在 end="" 上写成了 print(chunk)，每块都换行，看着像挤在一起
把类型注解里的 | 和管道符搞混 str | None 里的 | 是 Python 3.10+ 的联合类型；LCEL 的 | 是 Runnable 重载的 __or__。两者毫无关系 —— 但这是个好面试谈资：「| 能被重载，所以类可以自定义它的语义」
await chain.ainvoke(...) 报 SyntaxError 顶层代码不能 await，要用 asyncio.run(...) 包起来
想去翻老教程找 LCEL 章节，越看越乱 搜到的基本都是 v0.2 时代的 LLMChain / SequentialChain 写法。 看到这些词直接关掉，1.x 不用它们，别把你的代码写成过时样子
