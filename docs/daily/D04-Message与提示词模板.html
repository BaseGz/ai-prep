4动手 · 写 messages_demo.py

骨架已经放在 week1-basics/day04-messages/messages_demo.py，语法已校验通过。 文件里挖了 三处 TODO，其余部分（模型初始化、to_text、ask 函数）都已经写好。

今天真正的核心，是 ask() 里那三行：

history.append(HumanMessage(question))      # ① 用户这句话进历史
reply = llm.invoke(history)                 # ② 把「到目前为止的全部历史」发出去
history.append(AIMessage(to_text(reply)))   # ③ 模型的回答也进历史，下一轮才「记得」

没有任何魔法。所谓「记忆」，就是调用方每次都把整段历史重新发一遍。

三处 TODO

  1. 设计 3 个有依赖关系的问题 —— 第 1 轮给模型一个信息（比如你的名字），第 2 轮问它记不记得，第 3 轮基于前两轮追问。三个问题要互相依赖，否则测不出上下文有没有传对。
  2. 打印 history 的条数和累计 token —— 观察它怎么随轮数涨。这是「上下文有成本」的第一手证据。
  3. 跑一个对照组 —— 新开一个只留 system 的空历史，把同一句「我叫什么？」再问一遍。这一步是整个 D4 最有价值的地方：模型自己并不记得任何东西，拿掉 history 它就失忆。

提交消息模板（以后每天照这个填）

仓库里已配好模板文件 .gitmessage（commit.template 已指向它）。命令行 git commit 会自动带出； PyCharm 的提交框不一定会自动带，最稳的办法是每次从下面复制一份来填。

<type>(<scope>): 一句话标题（动词开头，50 字以内）

现象：
我以为：
做法：
结论：
槽位填什么
typefeat 新功能 ／ exp 对比实验 ／ fix 修 bug ／ refactor 重构 ／ docs 文档 ／ chore 环境 ／ test 测试
scopeday 编号（day04）或模块名（rag / langgraph / project / journal）
那个空行必须有。PyCharm 的提交框是一整个大文本框，Git 靠「第一行 + 一个空行」切标题和正文； 少了空行，整段会变成一条超长标题，git log --oneline 里糊成一团
现象发生了什么（报错 / 结果不对 / 效果差）。没踩坑就写「无」，别硬编
我以为这段最值钱 —— 你当时的错误判断，面试官能从中看出你是想过的
做法 / 结论最后怎么改的 ／ 一句话可复用经验（面试时直接说这句）

不是每天都要写满四段：踩坑的日子写全，顺利的日子两行也够（像今天 ③ 就只有三段：做了什么 / 对照组结果 / 结论）。

推送到 GitHub（首次）

  1. GitHub 右上角 + → New repository：名字 insta360-ai-prep、选 Public、 Initialize 那三个勾全部不勾（不加 README / .gitignore / license）
    为什么不能勾 README：你本地已经有一份 README.md 了（那份 GitHub 首页版）。 勾了的话 GitHub 会在远程先造一条初始提交，和你本地历史没有共同祖先，push 会被拒（non-fast-forward）， 得先合并再推，白折腾一轮。不是「不要 README」，是「不要在网页上新建一份」 —— 你本地那份要盖上去。 同理由：.gitignore 本地也有；license 要用 GitHub 模板的话，那是单独一条提交。
  2. PyCharm 菜单 Git → 管理远程… → + → Name 填 origin，URL 填 GitHub 给的 .git 地址
  3. Ctrl + Shift + K 推送 —— 首次会要求 GitHub 授权，授权一次即可
  4. 刷新 GitHub：README 应自动渲染成首页；再搜一次仓库里没有 sk- 开头的串

6坑预警

症状真实原因
第 2 轮模型答不出第 1 轮的信息 99% 是忘了把模型回复 append 回 history。只 append 了用户提问，模型看到的永远是一次性问答。
另一种「记不住」 每轮循环里新建了 history 变量，或者把 invoke 的返回值直接覆盖了 history。history 必须是循环外创建、全程同一个对象。
打印出来是一串奇怪的 list，不是文字 LangChain 1.x 的 content 可能是内容块列表而不是字符串。用骨架里的 to_text()，别直接 print(reply.content)。
又出现 LangSmith 401 刷屏 `.env` 里 LANGSMITH_TRACING 必须是 false。今天已经修过了，别改回去。
想用 create_agent 或 InMemorySaver 省事 今天禁止。框架帮你做了这件事，你就看不见它到底做了什么。D10 / D12 才轮到它们出场。
