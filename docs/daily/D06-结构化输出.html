4动手 · 写 struct_demo.py

新建 week1-basics/day06-structured/struct_demo.py。 骨架可以直接粘（下面这段我在你的 venv 里整段跑过了，输出见 4.2）；4.3 那三处要你自己改。 

"""D6 · 结构化输出：从一句话里抽出结构化线索

要验证三件事：
① Pydantic schema 怎么定义（字段名 + description 就是给模型的说明书）
② with_structured_output() 返回什么、拿到的东西怎么用
③ 抽出来的结果怎么直接驱动代码分支 —— 不再靠字符串匹配
"""
from __future__ import annotations

import os
from pathlib import Path
from typing import Literal

from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from pydantic import BaseModel, Field

REPO_ROOT = Path(__file__).resolve().parents[2]
load_dotenv(REPO_ROOT / ".env")

MODEL = os.getenv("DEEPSEEK_MODEL", "deepseek-chat")
BASE_URL = os.getenv("DEEPSEEK_BASE_URL", "https://api.deepseek.com")
API_KEY = os.getenv("DEEPSEEK_API_KEY")


class Lead(BaseModel):
    """从一句话里抽取出的客户线索。"""

    name: str = Field(description="客户姓名")
    company: str = Field(description="公司名称；原文没提到就填「未知」")
    need: str = Field(description="客户需求，用不超过 10 个字概括")
    urgency: Literal["高", "中", "低"] = Field(description="紧急程度")


def build_extractor():
    """建模型 → 把 schema 挂上去 → 返回一个能 invoke 的对象。"""
    model = init_chat_model(
        MODEL,
        model_provider="deepseek",
        base_url=BASE_URL,
        api_key=API_KEY,
        temperature=0,
    )
    return model.with_structured_output(Lead)


def route(lead: Lead) -> str:
    """拿到结构化结果之后，代码直接分支 —— 这就是今天要带走的东西。"""
    if lead.urgency == "高":
        return f"【立即跟进】{lead.name}（{lead.company}）→ 转销售主管"
    if lead.urgency == "低":
        return f"【进池子】{lead.name}（{lead.company}）→ 排进周报"
    return f"【今日回复】{lead.name}（{lead.company}）"


def main() -> None:
    extractor = build_extractor()
    print("① 返回对象类型：", type(extractor).__name__)

    text = "你好，我是远景科技的王磊，我们下个月要上线智能客服，想聊聊你们的方案，越快越好。"
    lead = extractor.invoke(text)

    print("② 抽取结果：", lead)
    print("   类型：", type(lead).__name__)
    print("③ 逐个字段点出来：")
    for k, v in lead.model_dump().items():
        print(f"   {k:<10} = {v}")
    print("④ 代码直接分支（没有一句字符串匹配）：", route(lead))


if __name__ == "__main__":
    main()

6坑预警

下面 4 条是我今天在你 venv 里实测出来的（不是猜的），输入输出都留了痕。

症状真实原因
结构化输出直接 400：
Thinking mode does not support this tool_choice		 用了 deepseek-flash。它是 thinking（推理）模式，不支持 tool_choice， 而结构化输出底层就是工具调用。换 deepseek-chat 即可 —— 这也和 D4 那条 reasoning_content 400 同源
method="json_mode" 报 400：
Prompt must contain the word 'json' in some form…		 json_mode 走的是 response_format={"type":"json_object"}， DeepSeek 要求提示词里出现「json」字样。今天不传 method（默认）就行； 默认实测走的是 tool calling
字段忘了写 description，不报错，但抽出来一塌糊涂 字段名 + description 就是给模型的说明书。实测把两个字段命名成 a / b： a 直接拿到整句原文，b 拿到一段它自己编的回复 —— 模型在瞎猜。 名字起得准，比写长描述更重要
以为 Field(ge=0, le=10) 只是本地兜底校验 约束会一起作为 JSON Schema 发给模型，所以模型会主动往范围里压： 实测让它给「100 分」，它回了 score=10。 是双保险，不是兜底 —— 别指望靠它挡住模型的胡说
ValidationError：模型没守 schema 少见但会发生（尤其字段多、嵌套深时）。看报错里是哪个字段，去改那个字段的 description，或把它收窄成 Literal。别加 try/except 糊过去
结果里少了某个字段 / 值写成了「未知」以外的东西 没在 description 里说明「抽不到怎么办」。要它填「未知」， 就得在 description 里明说 —— 模型的默认行为不是你以为的那样
又去翻到了 LLMChain / MultiPromptChain 之类的写法 0.2 时代的老教程。1.x 里这些类已经删了（你 D5 就记过一条）。看到直接关掉
