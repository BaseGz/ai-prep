① Interface 小节（3 分钟）

整页只有这一处讲 API，两个方法：

  • load() —— 一次性把全部文档读进内存，返回 list[Document]
  • lazy_load() —— 返回生成器，读一条给一条

为什么要有后者？因为 114 页不多，但一个公司的知识库可能是 11 万页。能流式处理的时候不要一次性全读进来，这是今天唯一需要记住的工程习惯。

② By category 下面的 Webpages / PDFs 两张表（7 分钟）

不用背，只看两件事：

  • 每个加载器名字后面都标了 Package 或 API —— 说明绝大多数加载器不在 LangChain 主包里，要单独装
  • 同一个格式有 四五个加载器（PDF 那行有 PyPDF / PyMuPDF / PDFMiner / PDFPlumber / Docling …）—— 它们解析同一份 PDF 的结果不一样，表格、扫描件、多栏排版的还原能力差很多

③ 那段 sunset 提示（10 分钟，今天最重要）

原文（未改写）：

PyPDFLoader, PyMuPDFLoader, PDFMinerLoader, and PDFPlumberLoader live in the unmaintained langchain-community package but should no longer be used. Prefer one of the partner packages above for new work.

翻译过来：官方让你别再用了，建议换 Docling / Unstructured 这类合作方包。

但今天你还是要用 langchain-community。这是一个明确的取舍，不是忽略警告：

1. 课程用的就是它。P34 / P35 的代码是 langchain_community.document_loaders，先对齐再迁移，否则你要同时学「加载器概念」和「换包」两件事。
2. 替代品的成本不在这 3 小时里。Docling 要下版面分析模型，Unstructured 在 Windows 上要 poppler、libreoffice、tesseract —— 装完可能今天什么都不剩。
3. 接口是一样的。load() / lazy_load() / Document(page_content, metadata) 是 BaseLoader 定义的，换包只改 import 那一行。

代价也要写清楚：每次运行顶部都会打一条 DeprecationWarning，而且这个包不再修 bug。 什么时候换？等你要处理扫描版 PDF、或者表格还原不准的时候 —— 那时你会自然地去找 Docling。

"""D16 · 文档加载：把 PDF / HTML / Markdown 变成 Document"""
import time
from itertools import islice
from pathlib import Path

from langchain_community.document_loaders import BSHTMLLoader, PyPDFLoader, TextLoader

ROOT = Path(__file__).resolve().parents[2]
PDF = ROOT / "datasets/raw/x4-manual-pdf/X4_UserManual_CN.pdf"
HTML_DIR = ROOT / "datasets/raw/x4-manual"
MD = ROOT / "docs/journal/2026-10-05.md"


def show(docs, n=1):
    """打印前 n 条：正文多长、开头是什么、metadata 有哪些字段"""
    for d in docs[:n]:
        print(f"  [{len(d.page_content):>5} 字] {d.page_content[:60]!r}")
        for k, v in d.metadata.items():
            print(f"      {k} = {str(v)[:60]}")


def load_pdf():
    t0 = time.time()
    docs = PyPDFLoader(str(PDF)).load()
    print(f"\n[PDF] {len(docs)} 条，{time.time() - t0:.2f}s")
    show(docs)
    return docs


def load_one_html():
    t0 = time.time()
    files = sorted(HTML_DIR.rglob("*.html"))
    docs = BSHTMLLoader(str(files[0])).load()
    print(f"\n[HTML 单页] {len(docs)} 条，{time.time() - t0:.2f}s  文件={files[0].name}")
    show(docs)
    return docs


def load_all_html():
    t0 = time.time()
    total, longest = 0, ("", 0)
    for f in sorted(HTML_DIR.rglob("*.html")):
        docs = BSHTMLLoader(str(f)).load()
        total += len(docs)
        if docs and len(docs[0].page_content) > longest[1]:
            longest = (f.name, len(docs[0].page_content))
    print(f"\n[HTML 全量] {total} 个 Document，{time.time() - t0:.2f}s")
    print(f"  最长一篇：{longest[0]} {longest[1]} 字")
    return total


def load_md():
    t0 = time.time()
    docs = TextLoader(str(MD), encoding="utf-8").load()
    print(f"\n[Markdown] {len(docs)} 条，{time.time() - t0:.2f}s")
    show(docs)
    return docs


if __name__ == "__main__":
    load_pdf()
    load_one_html()
    load_md()
    load_all_html()

耗时会在 0.4–0.9 秒之间浮动，数字对不上不用管；要盯的是这四个：

数字说明
42 条PDF 是一页一个 Document，不是整本一个。你拿到的是一本 42 页的手册，所以 42 条
1 vs 1 vs 1HTML 一个文件、Markdown 一个文件，各自只产出 1 条。同一个 load()，切分单位由加载器决定
16 / 2 / 1三种格式的 metadata 字段数：PDF 16 个（作者、创建时间、总页数…）、HTML 2 个（source、title）、Markdown 只有 1 个（source）
24 字PDF 第 1 页只有 24 字 —— 封面。它也会变成一个 Document，后面会污染检索

第 1 条：代码

feat(day16): 三种格式统一成 Document，先看清 metadata 再谈切分

现象：
114 页 HTML 加载成 114 个 Document、0.42 秒；PDF 42 页变成 42 条，首页只有 24 字；
HTML 每页开头约 100 字是「搜索您的问题 简体中文 English 日本語」这类导航，不是正文。

我以为：
加载器的作用是「把正文抽出来」，metadata 只是附带信息。

做法：
分别用 PyPDFLoader / BSHTMLLoader / TextLoader 加载三类文件，逐条打印 page_content 长度与 metadata；
统计 PDF 里正文少于 100 字的页；给每个 Document 补 section 字段（源路径第一段），再按栏目计数。

结论：
加载器不判断正文，它只做两件事 —— 决定切分单位（PDF 按页、HTML/MD 按文件）+ 把文件信息抄进 metadata；
三种格式的 metadata 字段数是 16 / 2 / 1，这个差别直接决定了后面能不能做过滤。
噪声和空页不会自动消失，得自己处理。

6坑预警

症状真实原因
每次运行顶部一段 DeprecationWarning: langchain-community is being sunset 不是报错，程序照跑。这是官方在提醒你包已停维护；第 3 节那段取舍就是解释这件事
